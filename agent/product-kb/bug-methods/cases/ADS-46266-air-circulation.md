# ADS-46266 空调“换新风”语义与项目能力边界

## 基本信息

- Jira：`http://jira.i-tetris.com/browse/ADS-46266`
- 模块：AI 大模型 / 语音 / 空调空气循环
- 原话：`空调吹久了闷，换新风`
- 当前 Jira 状态：重新打开，Resolution 未解决

## 证据

- 在线对话测试原话返回一条操作：`meta_id=1599`、`target=regular_ventilation`。
- 标准功能详情显示 `1599` 对应“打开定时通风”，语义包括驻车/定时/智能通风；其项目继承仅有江铃和东风，未继承深蓝。
- 深蓝 8155&8295 空调正式文档当前列出内循环、外循环、自动内外循环；“闷、换新风”应落外循环语义，不能把 `regular_ventilation` 当作外循环。
- Jira 日志中的离线链路“闷”识别为“吹脚”、下发 `meta_id=1071`，是独立的 ASR / 离线 NLU 问题，不能与云端功能点映射混为同一根因。

## 产品处理结论

- 将“换新风”定义为切换外循环，不定义为空气净化、驻车新风或定时通风。
- 转需求：新增深蓝项目“外循环”语音功能点；语音 NLU / 算法配置将“闷、换新风”落到该功能点，`1599` 不得复用。
- 离线链路“闷”到“吹脚”另转 ASR 排查。

## 可复用规则

1. 语音 bug 先区分在线云端结果、离线 ASR/NLU 结果和车端执行结果，不能只按最终“不支持”播报判断根因。
2. `meta_id` 必须继续核对标准功能语义和项目继承；同名或相近词不能替代字段语义核对。
3. 标准功能未继承深蓝时，不得把它当作深蓝现有能力；项目能力缺口按需求新增项目功能点。
4. 用户说“闷、透气、换新风”时，先按空气循环语义判断是否应落外循环；空气净化、驻车新风、定时通风属于不同能力，不自动混用。
