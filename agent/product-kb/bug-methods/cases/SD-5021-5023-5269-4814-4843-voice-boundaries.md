# SD-5021 / SD-5023 / SD-5269 / SD-4814 / SD-4843：多语言语音边界

## 适用范围

C673 G3/G5 多语言离线语音问题，涉及裸“音量”、DMS/OMS 疲劳提醒和丹拿均衡器预设。

## 证据与结论

- `SD-5269`、`SD-5023`：泰语/法语原话都是“把音量调到 50%”一类裸“音量”指令，Jira 评论明确提出缺少主体语义。当前处理口径是把裸“音量”定义为车内媒体/主音量，再由语音 NLU/标注统一多语言语义和槽位；两单合并追踪，不能把离线翻译结果直接当作车端执行问题。
- `SD-5021`：`meta_id=2805` 对应“打开特定 DMS/OMS 开关”，标准功能要求舱内监测已开启；深蓝项目功能点 `25106` 为继承未修改。C673 UI 仅有“疲劳提醒音”，且部分海外版本不能关闭疲劳提醒开关，因此“打开疲劳提醒”不能直接按通用 DMS 开关修执行，应先拆分疲劳提醒开关、提醒音、海外法规策略和 AIS/车端字段，再由 VUI/NLU、AIS、DMS/车端分别实现。
- `SD-4814`、`SD-4843`：rock、pop、人声属于均衡器预设语义，不是泛化“音效”；`SD-4814` 的法语问题可按语音 NLU/标准功能配置映射修正，`SD-4843` 因 Jira 未给原始波兰语 query，不能猜具体语料，先补原话后回归。

## 责任方

- 裸“音量”语义和多语言语料：语音 NLU/标注；必要时同步语音服务。
- 疲劳提醒开关/提醒音：VUI/NLU、AIS、DMS/车端按字段和系统边界拆分。
- 均衡器预设：语音 NLU/标准功能配置；车端只负责已正确下发后的执行验证。

## 复用边界

先读取当前 Jira 原话、离线/在线结果和正式 UI/功能定义。若语言、项目或车型改变，不能仅凭本案例套用默认音量主体或疲劳提醒策略；缺少原始 query 时不得猜语料。
