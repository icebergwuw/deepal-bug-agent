# Luo Zhiqin Bug Handling Style

来源：`罗稚钦工作说明.xlsx` 和历史培训材料 `agent/archive/training/peer-case-training-2026-07-06.md`。

## 风格结论

罗稚钦的处理方式偏资深产品快速定性：用很短的证据判断 bug 属于 `非问题 / debug / 转需求 / 转项目 / 修改用例 / 转回测试`，不在表里展开长推理。

## 可学习点

- 敢关无需求、无用例来源、测试预期错误的 bug。
- 对语义差异敏感，例如 `设置` 不等于 `打开`。
- 先判断测试预期是否成立，再决定是否转研发。
- 能把复杂背景压成一个处理动作。
- 对新语料、新规则、新前置条件，直接转需求。

## 不能盲抄

- 她的证据链有时太短，对 Agent 复盘不够。
- `debug` 有时过宽，需要在吴优表里明确是转语音、转研发、运营平台还是项目。
- `与客户确认 / 项目确认` 不能直接照抄，吴优表里仍要给当前产品立场和下一步。

## 吴优侧目标写法

- `收集到的信息`：Jira 现象 + 关键评论 / 文档证据。
- `预期处理方式`：产品结论 + 责任方 + Jira 动作。
- `状态`：`可关闭 / 转语音 / 转研发 / 转需求 / 待会诊`。
- `备注`：meta_id、相关票、需要问的人、复盘风险。
