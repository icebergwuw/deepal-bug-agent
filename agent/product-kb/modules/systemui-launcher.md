# SystemUI / Launcher / AppList

## 范围

- SystemUI：顶部状态栏、底部 dock、AppList、下拉快捷中心、控制中心。
- Launcher：桌面、3D 桌面、柔性桌面卡片、Launcher 页面跳转。
- 页面层级 / 弹窗优先级 / AppList 覆盖应用：通常需要产品定义优先级，再拆给 SystemUI / Launcher / 相关业务应用。

## 责任

- SystemUI：谢重任。
- Launcher / 3D 桌面：曾爽。
- 柔性桌面：李然明。

## 判断规则

- 评论里出现“UI 不参与页面优先级定义 / 需要产品确定”时，不能写“等产品确认”；如果用户要求 Codex 处理，要直接给产品定义。
- 如果当前行为是历史设计但用户预期合理，优先判断是否转需求，不要直接当 bug 修。
- AppList、卡片、弹窗、目标页之间的冲突，需要写清哪个页面/卡片应优先显示，以及触发后的关闭策略。

## 典型案例

- `SLV-43932`：深蓝管家链接卡片点击后消失。产品定义为点击链接后应优先完成跳转 / 目标页展示，不应仅因 AppList 层级直接关闭卡片；转需求给 SystemUI + Voice/UI 补页面优先级和弹窗关闭策略。
- `ADS-43148`：可见节点多个“关闭”语义触发多目标歧义，需产品定义优先级，并由可见可说 / 应用侧适配。
