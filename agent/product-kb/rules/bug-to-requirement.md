# Bug To Requirement Rules

## 转需求触发条件

- 当前需求 / UE / 配置表没有定义，但用户预期合理。
- 需要新增语料、新槽位、新前置条件、新车型差异策略。
- 历史设计如此，但客户要求改变体验。
- 多系统协同需要新增统一规则，如页面层级、可见节点优先级、隐私授权覆盖入口。
- 语音平台标准功能不覆盖目标能力，且不能只靠项目配置修复。

## HUR 文言与语料

长马海外文言吴优无权直接修改。不改文言表、Key 译文或车机文言，最多提出建议译文和理由，交中科修改。已判定要改的海外文言走翻译总票 bug 转需求。国内文言不走长马翻译总票，修复版本含「国内」即排除。0408 版本文言也不走，标题含 `【0408】`、`[0408]` 或 `0408分支` 即排除。现行 `01`–`21` 两句已相同，或评论已明确非问题、不是问题、符合标准、保持现状的，也不走。

原 Bug 关票是一定的。转需求 story 不按 Bug 张数新建：未传递给开发、经办人仍是 `you.wu` 时复用；已传递给开发才新建。长马文言和语料都这样判断。文言当前总票在 `agent/context.md`，会更新。细则见 `agent/product-kb/rules/hur-translation-parent.md`。

## 不转需求的情况

- 当前 PRD / UE / 配置表已有定义，研发未实现：转研发修 bug。
- 测试预期没有来源：关闭非问题或转测试改用例。
- 平台已有能力，仅 query / 泛化 / 项目继承缺失：转语音/NLU/运营平台配置。
- 下发正确但执行错：转应用研发。

## Epic

- 新建的转需求 story 按 `AGENTS.md` 写 Epic Link。目标项目有未关闭、标题正好是 `ECR_待签署` 的 Epic 时用它。
- 2026-11-12 吴优取消「不沿用原票 Epic」。同项目原票或参考票的 Epic 可以沿用。不套其他项目的票号。复用已有 story 时不改它的 Epic。
- 既没有这张 Epic，也没有同项目参考 Epic 时，先停下说明，不新建。

## 需求描述必须包含

- 原 bug 链接。
- 功能点 / PRD / UE / Alchemy 链接。
- 当前行为。
- 目标行为。
- 责任方。
- 如果是语音：query、`meta_id`、槽位、标准功能点、项目功能点。
