## 两件事分开

关票和建 story 不是同一判断。

- 关票是一定的。本次已判定的原 Bug 都要评论、关联当次 story，再按 Workaround / bug转需求关闭。不改原 Bug 经办人。
- 转需求 story 不按 Bug 张数新建。未传递给开发的 story 经办人是 `you.wu`，复用，不新建。已传递给开发，经办人不再是 `you.wu`，才新建，新建后的经办人仍是 `you.wu`。
- 长马文言和长马语料都用这个 story 判断。
- 不因为经办人是吴优，就关闭或新建吴优名下全部票。关的是本次已判定的原 Bug，不关 story。

语音执行失败、query 未执行、TTS 被状态退出截断、故事票、已关闭票、其他负责人的票，以及分类不确定的票，不关闭，也不新建。摘要里出现「截断」不能单独当成翻译票。

## 先定 story

1. 长马文言的当前总票只记录在 `agent/context.md`。执行前回读：仍未完成，且经办人仍是 `you.wu`。满足则复用，不新建单张需求。
2. 总票已关闭、已解决、不再收翻译问题，或经办人不再是 `you.wu`，都视为已传递给开发。先新建 story，把新票号写入 `agent/context.md`，再关联。不得沿用历史票号，也不得在流程正文把某个票号写成永久值。
3. 长马语料先搜覆盖同一模式、同一说法、且经办人仍是 `you.wu` 的未关闭 story。找到就复用，不新建。没有这种 story，且原 Bug 经办人仍是 `you.wu` 时，也不新建；原 Bug 还没交给开发。
4. 语料的覆盖 story 已传递给开发，或原 Bug 已传递给开发且没有仍在 `you.wu` 名下的覆盖 story 时，才新建 story。不得把 `HUR-86245` 或任何历史语料票写成所有语料问题的永久总票。

长马没有变更管理表页签时，不写深蓝页，不发飞书建票通知。这条不走变更表建票 skill。

## 再关原 Bug

1. 原 Bug 用 Relates 关联当次实际使用或新建的 story。已关联不重复建。
2. 原 Bug 评论写明原因、当次 story 链接、复用还是因为已传递给开发而新建，以及按 workaround / bug转需求关闭。
3. 解决结果用 Workaround。需要时先进入处理中再解决。保留原修复版本、QA 和严重程度，不改经办人。
4. 回读状态、解决结果、关联和评论。未回读不得说已关闭。

不回填吴优 bug 表。译文缺失的根因用需求遗漏；和翻译表不一致的根因用需求变更。语料差异先以 `agent/context.md` 的长马标准语料表为准。
