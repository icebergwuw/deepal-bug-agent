# 资料时效与证据边界

## 目的

避免把旧快照、缓存、历史会议措辞或文件修改时间当作当前产品事实。

## 执行规则

1. 当前 bug 结论优先级：当前 Jira 完整页面和评论 -> 生效 PRD/UE/项目资料 -> Alchemy 当前测试和功能点详情 -> 工作说明 -> 已沉淀案例 -> 历史会议记录。
2. “无需求文档”“当前不支持”“只有 MasterGo UE”必须写成一次核验结果：说明检索日期、已查入口和仍不可读的限制；不能写成永久边界。
3. `.mastergo/`、浏览器下载、截图缓存和旧导出物都不是正式资料；需要设计证据时重新读取当前 MasterGo 页面或 MCP。
4. 日期命名的会议、复盘和培训文档只保留当时事实与教学结论。当前路由与权限以 `AGENTS.md` 为准，证据以 `agent/evidence-contract.md` 为准，输出以 `agent/output-contract.md` 为准，流程以 `agent/workflows/` 为准，表格结构以 `agent/sheet-contract.md` 为准。
5. 每次形成可复用判断，日志至少写明读取来源、核验时间、无法读取的资料和未执行的外部动作。
6. 文件修改时间只能辅助发现风险，不能证明资料已核验；本地负责人索引只用于查重和定位，线上对应负责人页才是当前主数据源。
7. 同一 Jira 因负责人流转出现在多个负责人页属于正常历史，不作为数据错误；只检查同一负责人页内重复。
