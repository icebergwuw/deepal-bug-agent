# Bug Sheet Contract

当前版本与变更记录统一见 `agent/rules-version.md`。

注册表中 `active + read_write` 的负责人页统一使用本契约。线上页是主数据源，本地负责人索引只用于查重和定位。

## A:J 列职责

| 列 | 字段 | 规则 |
|---|---|---|
| A | 日期 | 本次新增或整理日期，`YYYY-MM-DD` |
| B | 问题jira链接+摘要 | `=HYPERLINK("http://jira.i-tetris.com/browse/<Key>","<Key>｜一句话摘要")` |
| C | 收集到的信息 | 现象 + 改变判断的决定性依据 + 精确证据位置 + 必要的规则空白；证据名称原位可点击；保持可扫读，不设硬性字数上限 |
| D | 产品Agent判断 | `agent/output-contract.md` 定义的唯一 `decision_text` |
| E | 准确率标注 | BOOLEAN 复选框，由人工评审 |
| F | 负责人判断 | 保留负责人原始判断，不用 Agent 覆盖 |
| G | 状态 | 一个短状态 |
| H | 复盘后的产品Agent判断 | `agent/output-contract.md` 定义的 `final_decision_text` |
| I | 备注 | 一个风险、待补边界或下一道门槛，约 40 字 |
| J | 相关文档 | 支撑 C、D 或 H 的 Jira、PRD/UE、Alchemy、工作说明等原始可追溯入口；仅显示可点击的短说明文字 |

一个 Bug 只占一行。不再新增 Agent 判断行、人工判断行或空白分隔行。

## 已有行更新模式

- 更新模式的唯一机器可读白名单在 `agent/config/sheet-update-modes.json`；允许列与保护列必须完整且互斥地覆盖 A:J，脚本、工作流和架构校验只消费该配置，不另写一份列集合。
- `普通二次复查 / recheck`：用户再次发送同一 Jira 或要求重新查看，且输入不是会议纪要、leader/客户复盘材料。重新核验当前 Jira 和决定性资料后更新当前阶段结果；D 保存新的 `decision_text`，H 保持复盘专用。
- `会议/复盘 / review`：用户提供会议纪要、可姐/leader 教学、客户复盘或明确复盘材料。D/F 保留初次判断和人工判断，H 保存 `final_decision_text`。
- 更新已有行必须使用列级定向写入，不得用 A:J 整行 payload 覆盖；写前核对负责人页、行号、B 列 Jira Key 和当前 A:J，写后回读 A:J。
- “保持不变”表示本次请求不得提交该列；不是先读取旧值再随整行写回。
- 预览后、真正发送 batchUpdate 前必须再次通过 `get_cells` 新鲜回读同一行完整 A:J，并用预览 fingerprint 对比；不一致就停止。Google Sheets 没有本流程可用的单元格原子条件写，写后仍必须立即回读。
- `agent/scripts/bug_sheet_contract.py` 的 `build / patch` 请求必须传当前负责人 `--owner-id`、本 Jira 已通过门禁且 key 一致的 schema v5 manifest 和同批次 `--run-bundle`。脚本同时校验本机身份、负责人范围、Jira/Drive短期访问回执、Drive检索回执、引用文档追查、版本族枚举、逐 Key 决策卡及表格行号；语音manifest自动要求Alchemy回执。任一门禁失败时不得生成写表请求。

## 内容规则

- C、D、I 不重复：现象、决定性证据和规则空白放 C，产品动作放 D，仍需推进的风险/门槛放 I；完整调查过程放日志。
- C 中出现的 `Jira`、`当前评论`、`关联原票`、PRD/UE 名称、Alchemy 结果、工作说明或其他证据名称必须直接绑定对应原始链接并可点击；不能只在 J 中另放链接。
- J 是 C/D/H 证据入口的汇总与兜底，不替代 C 列内联链接。
- D/H 的可见内容必须与 `agent/output-contract.md` 生成的当前阶段标准结论一致，不在表格契约中另定义一套文案。
- D/H 中的决定性依据使用“资料短名 + 精确位置”的可点击短标签，不显示长 URL；详细技术链和次要证据只放 C 或日志。
- G 使用 `待确认`、`待复核`、`待回归`、`可转研发`、`可转语音`、`可关闭`、`转需求`、`待会诊` 等短状态。
- H 只写复盘后的最终处理；不能覆盖 D/F。客户接受现状不等于研发已修复。
- J 只显示能说明来源和定位的短文字标签，例如 `Jira原票·描述`、`记忆空间PRD V0.7·2.2.4.2`、`情景模式UE V2.6·第13页`、`功能清单·情景模式序号938/939`、`Jira视频·00:02-00:06`；标签文字本身必须可点击，禁止在 J 显示原始长 URL。
- J 有多个入口时每行一个短标签，并使用同一单元格内的富文本多链接；每个标签分别绑定对应原始 URL。
- 若用户实际界面无法点击短标签，不得把长 URL 铺回 J；应修复富文本链接元数据、标签范围或写入方式，直到文字标签本身可点击。不得用蓝色或下划线样式冒充可点击链接。
- C、D 或 H 引用了某项正式资料或平台结果时，J 必须包含对应原始入口；无法提供可访问链接时，在 C 或 I 明确读取限制。
- J 只有一个入口时可使用单个 `HYPERLINK` 公式；有多个入口时必须使用一个单元格内的富文本多链接。禁止用 `HYPERLINK(...)&HYPERLINK(...)` 拼接多个入口，因为 Google 表格会只保留显示文字而丢失各段可点击链接。

## 固定样式

- 表头 A1:J1：深色藏蓝底、白色 Arial 10 粗体、居中、自动换行、内边距 `6/8`。
- 数据区：白底、Arial 10、垂直居中、自动换行、内边距 `6/8`、浅灰细边框。
- A/B/E/G 居中；C/D/F/H/I/J 左对齐；G 加粗。
- B 为蓝色下划线链接；E 只保留复选框，不用颜色表示准确率、状态或优先级。
- 不保留数据区绿色条件格式。
- 数据行使用“适合数据”自动行高，不设置单行固定像素。
- 新增行必须复制负责人注册表 `format_anchor_row` 指定的固定格式锚点；吴优 `bug` 页唯一锚点为第 107 行（Sheets API 0-based 索引 106）。不得改用上一行、最近行、空白行、分隔行或表头。复制仅用于格式，A:J 内容和 E 列 BOOLEAN 验证仍须按列契约结构化写入。
- 禁止用剪贴板 HTML/纯文本作为新增行的最终写入方式。C、D、H、J 的短标签必须通过结构化富文本链接写入，E 必须使用 BOOLEAN 数据验证；写入后必须在实际页面视觉回读一次，确认长文本未被固定行高截断。

## 页面 /save 写入

结构化 Sheets API 仍是默认写表路径。API 写或读被实际阻断，且操作者当前 Chrome 已登录目标表格时，先用 `agent/scripts/sheet_page_save.py` 走页面自己的 `/save`，不要先退回逐格手写。

已证实、可以生成命令的只有三类：纯文本、以 `=` 开头的单个公式（含一个 `HYPERLINK`）、清空。命令在页面内读取当前 `/bind` 或 `/save` 地址和会话，不把 sid、token、ouid 写入仓库、日志或聊天。一次请求只改一个单元格；修订号用本次响应里的新修订号继续，不把旧修订号写死。

页面 `/save` 还不能表达富文本多链接、BOOLEAN 复选框验证和锚点行格式复制。这些格子继续走下面的 Chrome 界面兜底。页面保存成功只说明服务端接受了这次命令，必须重新选中单元格或重新加载后读取公式栏；不能把它叫作 API final，也不能冒充 `--phase ui`。

## Chrome 界面写入兜底

结构化 Sheets API 仍是默认写表路径。只有 API 写或读被实际阻断，且页面 `/save` 不能表达目标单元格时，才允许 `chrome_ui` 兜底。阻断必须原文记录，至少包含 `gapi` 无 token、`SAPISIDHASH` 400、`ERR_BLOCKED_BY_CLIENT` 或 `batchUpdate` 未能发送之一。证据门禁、身份预检和决策核验卡不因改走界面而跳过。

界面写入不是 API final 的替代证明：

- 截图、视口裁切和相邻列溢出不能证明单元格为空、已写入或链接可点。必须逐列读取公式栏原文。
- 富文本链接必须进入编辑态，读取 `data-sheets-formula-bar-text-link` 或等价链接元数据；读完按 Esc 退出。Enter 会提交单元格，不能当换行，也不能用来结束核对。
- 名称框跳转前先退出编辑态。地址超出工作表大小时停止，不得把停留在旧单元格上的公式栏当成目标格。
- 格式刷只复制注册表锚点行的格式，不复制值。新增行 F、H 写后必须为空；复查不得改 F/H；复盘只允许改 H。写进其他票标题时必须清空并标记 `contamination_cleared`。
- E 必须仍是 BOOLEAN 复选框。行高按内容撑开。选区收回单个 A:J 单元格。已有基础筛选必须覆盖目标行；当前没有筛选时只记录，不擅自给共享表新建筛选。
- 收口使用 `validate_bug_run.py --phase ui`，status 为 `ui_verified`。不得报告 `validate_bug_run.py --phase final` 已通过。
- 基础筛选覆盖 A:J 的全部已填行。数据边界的绿色横线优先检查筛选范围，绿色框优先检查页面选区。

## 写后校验

1. 回读本次 A:J 内容和 B 公式。
2. 验证 E 列 BOOLEAN 数据校验。
3. 验证自动行高、对齐、边框、条件格式和基础筛选范围；不得用固定像素行高掩盖换行问题。
   新增行还必须回读固定锚点与目标行，并逐列核对日期格式、背景色、边框、内边距、水平/垂直对齐、换行、字体、字号、粗体及基础文字颜色；B/C/D/H/J 的链接 URI 和局部富文本链接样式按内容单独校验，不要求与锚点 URL 相同。任一固定格式字段不一致时停止收口，先以锚点格式修复再重新回读。
4. 页面选区收回单个活动单元格。
5. 在 `agent/logs/bug-actions/` 记录写入位置和回读结果。
6. 回读 J 的 `hyperlink` 或 `textFormatRuns[].format.link.uri`，确认每个短标签都有正确目标；只有标签文字或公式文本、没有链接元数据，不算通过。
7. 用户反馈链接不可见或不可点时，必须按用户实际界面复核并修复短标签的链接元数据或写入方式；J 仍不得显示完整 URL，不能以标签有颜色或仅存在 API 元数据为由结束处理。
8. 回读 C 的 `textFormatRuns[].format.link.uri`，逐项确认 C 中每个证据名称原位可点击且目标正确；J 有链接但 C 内证据不可点，不算通过。
9. 回读 D/H 的 `formattedValue` 与 `textFormatRuns[].format.link.uri`：可见文本必须与 `agent/output-contract.md` 一致；每个依据短标签必须绑定正确原始链接，单元格不得显示长 URL。
10. API 路径保存本次原始 A:J 回读和校验 JSON，在 run bundle 中登记路径与 `readback_sha256`；只有 `validate_bug_run.py --phase final` 通过后才能报告 API 写表完成。`chrome_ui` 路径改为保存逐列公式栏回读，登记 `ui_readback_sha256`，并通过 `validate_bug_run.py --phase ui`；这条通过不能称作 API final 通过。页面 `/save` 只记录修订号和公式栏回读，同样不能称作 API final 或 ui 通过。
11. 更新已有行时对比写前、写后 A:J：除当前模式允许且实际声明修改的列外，其余列的值、公式和富文本链接必须一致。
