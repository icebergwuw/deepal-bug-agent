## Process Rules Learned

- 会议反馈要沉淀为规则，而不是只修改当前行。
- 旧判断如果被 leader 纠正，要在准确率标注里记录错误原因。
- 对视频附件相关 bug，要优先尝试在线预览视频，不要只靠文字描述。
- 复盘后结论必须写入 `复盘后预期处理方式` 列，不能覆盖原始 Agent 判断列。
- 开发要求产品确认类别/语义时，不要让吴优列全量类别表；按本单原话给关键词兜底范围并直接评论到 Jira，例如 PC-37176 的 `barbershop` 范围为 `理发、美发、发型、造型、剪发、发廊、发屋、Hair Salon、Barber`，评论后转程云。
- bug 表结构必须一个 bug 一行，人的判断、Agent 判断和复盘结论都用列管理，不能又用行又用列。
- 拨号类问题取 `with_number.canonical` 作为执行号码，literal 只作识别/显示参考。
- 多语言问题要先区分本地可控文案和手机/系统返回数据；若字段确实读取手机系统数据且车端不可控，可接受现状关闭。
- 已登记的阿语文案问题保持 Pending，等周俊岩登记的新版本回归验证，不要改成关闭或转需求。
- bug 转需求要新建需求并关联原 bug；原 bug 按 workaround/bug转需求关闭。
