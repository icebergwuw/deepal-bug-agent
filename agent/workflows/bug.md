# Bug Workflow

当前版本与变更记录统一见 `agent/rules-version.md`。

这是 Jira Bug 调查、产品判断、清单更新和留痕的唯一流程文件。

## 1. 识别意图与负责人

1. 用户说“看 Bug 列表 / Bug 清单 / 待处理 Bug”且没有提供具体 Jira Key 时，先打开 `agent/context.md` 登记的 Jira Dashboard 17302；只读取用户指定范围，不因打开列表自动处理全部条目。
2. 用户只发具体 Jira Bug 链接时，默认执行完整流程并更新对应负责人清单。
3. 用户再次发送同一 Jira 或要求“再看 / 重新确认 / 二次处理”，只要输入不是会议纪要、leader/客户复盘材料，就继续走本流程；重新读取全部当前证据后可改原行 C、D、G、I、J。
4. 用户明确要求只读时，停在证据整理，不写表、不评论或流转 Jira。
5. 当前负责人优先按用户指定；未指定时读取 Jira 当前经办人的显示姓名，用 `agent/bug-owners/registry.yaml` 的 `jira_display_names` 匹配；账号只作可选兜底。只有 `active + read_write` 可进入默认写表流程。
6. 未匹配到人员时新增 `pending` 配置并停止写表，不得临时写入其他负责人页；`reference` 人员只参与资料检索。
7. 先查当前负责人线上页和本地索引。同页已有 Jira 就更新原行，没有才新增。
8. 跨负责人重复是正常流转历史：不删除其他负责人页记录，不把它作为异常；仅处理当前负责人页内重复。

## 2. 完整读取 Jira

必须读取标题、状态、优先级、模块、车型、描述、复现概率、附件信息、已有定责和全部评论。

- 评论按时间顺序提炼，不能只看最后一条。
- “需要产品确认 / 产品定义 / 设计如此 / 历史如此 / 若调整需下需求 / 研发不定义”等评论是核心证据。
- 评论要求产品确认时，Codex 直接给吴优的产品结论、责任方和动作，不把问题退回产品。
- 无法读取的附件或页面要记录限制，不猜内容。

## 3. 补充产品证据

1. 从当前 Jira 提取模块、车型、版本、query、`meta_id`、页面、责任方和评论关键词。
2. 完整执行 `agent/evidence-contract.md`，按问题类型核对正式定义、当前实现和规则空白。
3. 用 `agent/product-kb/` 发现资料入口、责任边界和相似案例，但只复用检索方法；最终判断必须回到当前 Jira、生效正式资料和当前平台结果。
4. 证据未达到对应结论门槛时停止写确定性结论，改为记录具体缺口、责任方和下一步。

## 4. 做产品判断

- 先判断测试预期是否成立，再判断是非问题、现有方案可接受、研发缺陷、配置/NLU缺失还是新需求。
- 按 `agent/output-contract.md` 形成一次结构化结果和唯一 `decision_text`。
- UI 已有能力但语音未覆盖，按语音需求变更处理，并附项目功能点、query、当前行为和目标行为。
- `typeCode/类别语义/关键词映射` 卡点，按当前 bug 的 query、槽位、canonical 给本单可执行范围，不扩成无依据的全量类别表。
- 具体 Jira 的既有词表、责任人和案例口径只从 `agent/product-kb/` 当前条目读取，不在通用流程中写死。

## 5. 更新负责人清单

- 严格按 `agent/sheet-contract.md` 写当前负责人页。
- 已有 Jira 更新原行；新 Jira 追加一行。写后回读 A:J，核对 B 公式、E 复选框、列位、行高和筛选边界。
- 普通二次复查更新 C、D、G、I、J；保留 A、B、E、F、H。D 写本次重新核验后的当前 `decision_text`，不是把新结论绕写到 H。
- 同步对应 `agent/bug-owners/<owner>/index.md`。索引以线上页为准，不凭历史静态清单追加。
- 只改当前流程允许且本 Bug 必需的列，不覆盖 E/F；H 只由会议/复盘流程更新。

## 6. 外部动作与日志

- 遵守 `AGENTS.md` 的全局外部动作权限；Jira 评论、转派和状态修改均需用户明确授权。
- 外部动作的文本复用、链接和回读按 `agent/output-contract.md` 执行。
- 每批操作在 `agent/logs/bug-actions/` 留日志，记录负责人、每一个 Jira key、证据、线上位置、写入摘要、回读校验和未执行动作。
- 批量任务必须在日志正文逐条列 key，或引用同目录 manifest；manifest 至少包含 Jira key、负责人、表格行号。范围描述不能替代逐条清单。
- 旧线上数据没有日志时不伪造补录；标为历史未审计，后续触及时再按完整流程核验并留痕。

## 交付前检查

- 站在吴优产品视角，未出现“请产品确认”。
- `agent/evidence-contract.md` 的当前问题必查链路和结论门槛已满足。
- `agent/output-contract.md` 的唯一结论、责任方和渠道复用已满足。
- `agent/sheet-contract.md` 的列位、链接、样式和回读已通过。
- 已查当前负责人页内重复；跨负责人同 Jira 保留。
- 已回读写入结果并记录日志。
- 已回读日志，确认本次处理的每一个 Jira key 都可检索到。
- 经授权执行的 Jira 外部动作已按 `agent/output-contract.md` 回读；未经授权未执行。
