# Bug Output Contract

当前版本与变更记录统一见 `agent/rules-version.md`。

这是 Bug 结构化结论、D/H、Jira 流转说明、操作日志和用户回复格式的唯一权威文件。其他规则只决定何时产生或使用结论，不得另写一套输出格式。

## 结构化结果

每个 Bug 只形成一份结构化结果：

- `evidence_summary`：现象、改变判断的决定性依据和必要的规则空白。
- `decision_text`：初次产品结论，一个主动作和一个明确责任方。
- `status`：一个短状态。
- `boundary_text`：唯一未决风险、适用边界或下一道门槛。
- `technical_evidence`：详细日志、字段、执行链和调查过程。
- `final_decision_text`：仅在复盘或后续反馈改变最终处理时形成。

## 唯一结论

- 初次处理以 `decision_text` 为唯一标准结论，写入 D。
- 普通二次复查仍属于当前判断更新：重新形成 `decision_text`，按 `recheck` 模式替换当前阶段结果；不因是第二次查看而改写 H。
- 发生复盘后，以 `final_decision_text` 为唯一最终结论，写入 H；D/F 保留历史。
- 同一阶段的表格、Jira 流转说明、日志和聊天必须复用同一份可见文本，不能分别概括多版。
- 输出必须站在本机已绑定操作者的产品负责人视角，直接定义功能边界、动作和责任方；不写“请产品确认 / 产品定口径 / 建议产品判断 / 研发看下”。
- 一个 Bug 只保留一个主动作和一个责任方；涉及不同系统责任边界时拆票。

## 结论格式

`decision_text` 和 `final_decision_text` 统一使用：

```text
结论：<产品判断及适用场景>
依据：<改变结论的可点击资料短标签>
处理：<目标行为或具体动作>；<明确责任方>处理。
```

- 必须能脱离 C、I、J 单独看懂当前场景、目标行为、动作和责任方。
- 依据只保留会改变结论的关键来源，并在短标签中带可复查位置（页码/章节、Sheet/序号/Key、UE 页面/图层、附件时间码等），不复制完整调查过程。
- 来源显示可读短标签，不显示长 URL；短标签必须绑定原始可访问链接。
- 没有可访问链接时，在结论或唯一风险中简要说明读取限制，不能伪装成已核实证据。

## 各渠道复用

### Bug 表

- D 原样保存 `decision_text`；H 原样保存 `final_decision_text`。
- 富文本链接、列位和回读要求由 `agent/sheet-contract.md` 执行。

### Jira

- 只有用户明确授权时才评论、转派或修改状态。
- Jira 评论复用当前阶段的 D/H 可见文本；若编辑器没有保留表格富文本链接，重新给同一短标签绑定原始 URL，不重新改写结论。
- 用户只问“我要怎么回”时，返回同一结论的可粘贴版本，不执行外部动作。

### 操作日志

- 日志保存当前阶段的 D/H 原文，并在独立段落记录详细证据、表格位置、回读、执行动作和未执行动作。
- 日志中的技术调查不能替代标准结论，也不能制造第二版结论。

### 用户回复

完成写表并回读后，默认首段为：

```text
<Jira Key>：<回读的 D 原文>
```

发生复盘并回读 H 后，改为：

```text
<Jira Key>：<回读的 H 原文>
```

只读模式使用本轮已形成但未写表的 `decision_text`，并明确未写表。阻塞模式直接说明缺失的决定性来源及影响，不猜结论。

Chrome 界面兜底写入并完成 `validate_bug_run.py --phase ui` 后，首段仍是回读到的 D 原文。下一句必须写明这是界面回读，且未通过 API final。不得把界面回读说成脚本 final 通过。

聊天中 D/H 的可见文字必须与回读原文一致；需要可点击时，按 J 中的原始目标重新绑定同名短标签，不能通过改写正文增加另一版结论。

## 允许追加的信息

主结论之后，只在用户明确要求或会影响下一步时追加：

- 用户点名要求挖出的文档或依据；
- 线上表格写入位置和回读结果；
- Jira 评论、转派、状态变更的实际执行结果或明确未执行状态；
- 唯一阻塞项或下一步门槛；
- 批量任务的逐 Key 完成/部分完成状态。

追加信息不能重复解释结论、扩大责任范围或替代 D/H。默认不展示内部工作过程、冗长日志路径或无关来源。

## 批量与复盘

- 批量 Bug 每个 Jira Key 单独一段，逐条复用各自行的 D；有复盘时逐条复用 H。
- 复盘材料可另外给“结论更新 / 当前操作者待办 / 准确率标注 / 规则沉淀 / 待补信息”，但每个 Bug 的最终处理原文仍来自 H。
- 如果聊天必须换一种说法才能让用户看懂，应先修正表格中的 D/H并重新回读，不能只在聊天中补救。
