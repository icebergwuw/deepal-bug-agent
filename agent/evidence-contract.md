# Bug Evidence Contract

当前版本与变更记录统一见 `agent/rules-version.md`。

这是 Bug 证据深度、来源优先级和关闭门槛的唯一权威文件。`AGENTS.md`、工作流、表格契约和 Skill 只引用本文件，不复制一套证据规则。

## 证据分类

每个 Bug 都必须区分：

1. `正式产品定义`：当前生效的主 PRD、专项 PRD、交互文档、可读 UE、项目配置或功能点明确规定的目标行为与适用边界。
2. `当前实现事实`：Jira 描述、评论、日志、截图、视频、可复现结果和研发说明证明当前如何运行。
3. `规则空白`：正式资料未定义、资料不可读、入口失效、版本不明或多个正式来源互相冲突的部分。

研发所说“当前逻辑如此 / 可见优先 / 设计如此 / 历史如此 / 若调整需需求”只能证明实现、历史或调查方向；没有生效正式资料或客户最终结论时，不能单独作为关闭、非 Bug 或设计如此的依据。

## 来源优先级

1. 当前 Jira 的字段、描述、附件和完整评论时间线。
2. 生效主 PRD及与本问题直接相关的专项 PRD、交互文档、UE、配置和项目资料。
3. Alchemy 当前在线结果、标准功能和深蓝项目继承功能点。
4. 当前工作说明及其原始资料入口。
5. `agent/product-kb/` 中当前为 `verified` 且适用范围匹配的条目。
6. 历史案例、会议、培训、快照和 archive，仅作检索线索与历史证据。

不能用低优先级来源覆盖当前 Jira或生效正式定义。文件修改时间不是资料有效性的证明。

## 必查深度

- 每份正式资料必须落到会改变判断的具体章节、条款、图层、配置项或功能点，记录文档名称、版本、适用范围和原始入口。
- AI 大模型、地图出行、跨域交互等存在专项资料的模块，除主 PRD外还必须按 query、功能名、`meta_id`、页面和交互阶段检索直接相关的专项资料。
- 判断测试预期前，先核对用户场景、车型、版本、当前行为和目标行为是否在同一适用范围。
- 找不到或读不到资料时，记录检索日期、已查入口和具体限制；“未读到”不能改写成“没有定义”。

## 语音 / NLU / VUI

1. 在 Alchemy 在线对话输入 Jira 用户原话，读取 `classification`、`operations`、`meta_id`、槽位和返回结果。
2. 用 `meta_id` 打开标准功能详情。
3. 有深蓝项目继承功能点时继续读取项目详情，核对设置项、范围、泛化、执行策略、TTS 和状态。
4. 同时核对生效主 PRD及直接相关专项 PRD/交互文档；Alchemy 只证明语义和配置，不能单独证明产品交互目标。
5. 结论必须明确落到 ASR、NLU/标注、DS/功能点、项目执行策略、TTS、车端执行或新增需求。

项目参数、范围、执行策略或 TTS 差异优先落到项目继承功能点；标准元数据、slot、intent、tagging 或拆分问题落到标准功能/NLU责任边界。具体责任映射从 `agent/product-kb/org/component-owner-map.md` 读取，不在本契约写死人员。

## MasterGo UE

1. 优先从当前工作说明或 Drive 资料取得 MasterGo 短链或 `fileId + layerId`。
2. 只有 `page_id` 不能证明目标图层已读；MCP 返回空结构、文件在草稿箱、账号无团队项目权限或链接信息不足时，记录“未读到 UE”并补要图层链接或短链。
3. `.mastergo/` 本地缓存不是正式资料。
4. token 只通过安全运行时配置注入，不写入表格、日志、知识库、项目文件或回复。

## 结论门槛

- `可关闭 / 非 Bug / 设计如此`：必须有生效正式定义、明确适用边界或客户最终结论。
- `可转研发 / 可转语音`：必须写清当前行为、目标行为、缺陷位置和责任边界。
- `转需求`：必须证明现有正式能力或范围未覆盖目标行为，并按不同系统责任边界拆票。
- 证据不足但仍可能改变判断时，保持 `待复核 / 待确认 / 待会诊`，在唯一风险中写明缺口、责任方和下一步。

## 可追溯要求

- 改变判断的来源必须保存原始可访问链接；资料不可访问时保存来源限制。
- 证据如何写入 C/D/H/J 由 `agent/sheet-contract.md` 定义。
- 结论如何在表格、Jira、日志和聊天中复用由 `agent/output-contract.md` 定义。
- 详细技术链进入 `agent/logs/bug-actions/`，不能只留在聊天上下文。
