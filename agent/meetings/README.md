# Meeting Notes

这个目录专门存放吴优的会议纪要、可姐/leader 教学、bug 复盘和会后待办。

## 存放规则

- 每次会议单独建一个文件，命名格式：`YYYY-MM-DD-主题.md`。
- 不同类型统一放这里，不再散落在普通规则文件里：
  - `教学`：可姐/同事教的方法、产品判断方式、案例讲解。
  - `复盘`：leader 对 Agent 判断的对错反馈、bug 结论修正。
  - `后续反馈`：已处理 bug 收到吴优、客户、可姐或 leader 的最终结论，沿用复盘结构更新原 bug 的 H 列。
  - `待办`：吴优会后要做的 Jira 评论、转单、建需求、拉群、表格更新。
  - `规则沉淀`：以后处理同类 bug 要复用的方法。
- 每次会议纪要都要同步更新 `action-items.md`，把吴优需要执行的事项列清楚。
- 如果会议里修正了 Agent 规则，按职责更新证据契约、输出契约、工作流、表格契约或产品知识库；不要在会议文件里另建一套现行规则。

## 会议纪要标准结构

每份会议纪要按下面顺序写：

1. `会议信息`：日期、来源、参与人、主题。
2. `一句话结论`：这次会议最重要的产品结论。
3. `结论更新`：逐条 bug 写最终结论、责任方、相对旧判断的变化。
4. `吴优待办`：只写吴优下一步要做什么，动作要能直接执行。
5. `Jira 注释草稿`：需要评论 Jira 时，直接给可复制文本。
6. `准确率标注`：Agent 判断对/错/待定及原因。
7. `规则沉淀`：以后同类问题如何判断。
8. `待补信息`：会议中没讲清、后续还要查的资料。
