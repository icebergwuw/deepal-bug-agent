## 规则沉淀

- 会议反馈要单独沉淀到 `agent/meetings/`，并同步更新 `action-items.md`。
- 旧判断如果被 leader 纠正，要记录准确率标注和错误原因。
- 对视频附件相关 bug，要优先尝试在线预览视频，不只靠文字描述。
- bug 表结构要一条 bug 一行，人的判断、Agent 判断和复盘结论都用列管理，不能又用行又用列。
- 复盘后结论写入 `复盘后预期处理方式` 或独立复盘列，不能覆盖原始人工判断和原始 Agent 判断。
- 开发要求产品确认类别/语义时，不要让吴优列全量类别表；按本单原话给关键词兜底范围并直接评论到 Jira。
- 拨号类问题优先看语音平台返回的 `with_number.canonical`，执行端应取 canonical，不取可能混乱的 literal。
- 多语言/阿语问题要区分“本地翻译缺失”和“手机/系统数据返回”；如果字段读取手机系统数据且车端不可改，可接受现状关闭。
- bug 转需求必须关联原 bug；原 bug 按 workaround/bug转需求关闭，需求内容可先占位，后续评审补全。
