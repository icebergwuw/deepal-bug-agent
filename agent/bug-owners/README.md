# Bug Owner Management

`registry.yaml` 是人员、路由状态和数据源的唯一注册表。人员名单不得再写死在 `AGENTS.md` 或工作流里。

## 状态

- `active`：参与当前 Jira 路由，可按默认流程更新线上清单和本地索引。
- `reference`：只用于案例和资料检索，不自动接收 Jira，也不写回其工作说明。
- `pending`：人员已知，但 Jira 账号、当前清单或写回规则未确认。
- `inactive`：不接收新 Bug，历史资料保留。

`write_mode` 再控制具体权限：只有 `status: active` 且 `write_mode: read_write` 才允许按默认 Bug 流程写负责人清单。Jira 评论、转派和状态修改仍需用户明确授权。

## 新增人员

1. 在 `registry.yaml` 增加唯一 `id`、姓名、Jira 经办人显示名、状态和写入模式；账号可选。
2. 确认当前主数据源：文件 ID、文件类型、准确页签和负责人模块资料。
3. 在 `<id>/README.md` 记录查询入口、资料入口和读取限制。
4. `active` 人员首次加入时，完整读取线上清单并生成 `<id>/index.md`，校验同页重复。
5. 记录初次同步日期、行数、读取方法和未执行动作。
6. 人员转岗时改为 `inactive`，不删除目录、索引或历史日志。

## 同事独立使用

- 从 GitHub 使用本流程、但不是已登记负责人、也不使用已登记 Bug 表的人，不写入 `registry.yaml`，不登记为 `active`。
- 只在已忽略的 `local-profile.json` 记录对方明确说出的姓名、`operator_mode: external` 和结果位置。没确认使用人是谁、以及结果在哪里更新之前，不创建或修改任何表格。
- 对方没有现成表格时，新建本地 Excel，字段仍用 A:J。有自己的表格时只写那个位置。两种情况都不得写入其他负责人的清单。
- 处理中如果 Jira 当前经办人匹配不到注册表，仍把经办人记为 `pending`。`pending` 只表示这个经办人的团队清单还没确认，不授权把同事结果写进别人的表。

## 路由规则

- 用户指定负责人时优先使用指定人员；未指定时按 Jira 当前经办人的显示姓名匹配 `jira_display_names`，账号仅在需要消歧时兜底。
- 未匹配人员先登记为 `pending`，不得临时写入其他人的清单。
- 同一 Jira 出现在不同负责人页是正常流转历史；只检查当前负责人页内重复。
- `reference` 人员的内容可用于校准产品判断，但不能替代当前 Jira 和正式资料。
- 负责人页有固定格式锚点时，在 `registry.yaml` 使用 1-based `format_anchor_row` 登记；新增行只能复制该行格式，不得临时改用上一行、最近行或空白行。吴优 `bug` 页固定以第 107 行为锚点。

新增人员使用 `owner-template.md`，不要复制某位现有人员的特殊配置。
