# Bug Action Logs

这里记录 Codex 对 bug 工作区的可追溯操作。

## 什么时候写

- 新增或更新 `bug` 表。
- 评论 Jira 或流转 Jira。
- 修正 `AGENTS.md`、证据/输出/表格契约、`agent/workflows/`、Skill、机械脚本或产品知识库。
- 沉淀可复用案例、会议复盘、准确率标注。
- 批量整理表格结构或样式。

## 推荐格式

```md
# YYYY-MM-DD 主题

- 操作者：Codex
- 涉及 Jira：ADS-xxxxx / PC-xxxxx / 无
- 操作类型：只读 / 新增表格行 / 更新表格行 / 评论 Jira / 流转 Jira / 规则维护 / 知识库沉淀
- 读取证据：Jira 描述、评论、附件、工作说明页签、Alchemy meta_id、知识库文件等
- 表格位置：bug!Axx:Jxx
- 写入摘要：写入或修改了什么
- Jira 动作：评论原文、流转动作、目标责任人、执行结果；没有执行则写“未评论 Jira / 未流转 Jira”
- 回读校验：是否已回读，结果如何
- 未执行动作：未评论 Jira、未流转 Jira、未更新表等
- 敏感信息处理：未记录账号、密码、token 或访问口令
```

## 规则

- 日志要短，但必须能倒查“为什么这么写”。
- `涉及 Jira` 必须显式列出本次处理的每一个 Jira key；批量任务过多时可以引用同目录的 manifest，但 manifest 必须逐条列 key、负责人和表格行号。
- 只写“更新某段范围 / 批量处理若干条”而没有 Jira key，不计入该 Bug 的可追溯日志覆盖。
- 不记录账号、密码、token、测试账号明文或平台访问口令。
- 不可访问的资料也要写清楚限制，例如“仅 MasterGo 链接，当前不可读”。
- 旧线上记录缺少历史日志时不伪造补录；在后续触及该 Jira 时按完整流程核验并从当次开始留痕。
