# Bug Action Logs

这里记录 Codex 对 bug 工作区的可追溯操作。

## 什么时候写

- 新增或更新 `bug` 表。
- 评论 Jira 或流转 Jira。
- 修正 `AGENTS.md`、证据/输出/表格契约、`agent/workflows/`、Skill、机械脚本或产品知识库。
- 沉淀可复用案例、会议复盘、准确率标注。
- 批量整理表格结构或样式。

## 推荐格式

```md
# YYYY-MM-DD 主题

- 操作者：Codex
- 涉及 Jira：ADS-xxxxx / PC-xxxxx / 无
- 操作类型：只读 / 新增表格行 / 更新表格行 / 评论 Jira / 流转 Jira / 规则维护 / 知识库沉淀
- 读取证据：Jira 描述、评论、附件、工作说明页签、Alchemy meta_id、知识库文件等
- 表格位置：bug!Axx:Jxx
- 写入摘要：写入或修改了什么
- Jira 动作：评论原文、流转动作、目标责任人、执行结果；没有执行则写“未评论 Jira / 未流转 Jira”
- 回读校验：是否已回读，结果如何
- 未执行动作：未评论 Jira、未流转 Jira、未更新表等
- 敏感信息处理：未记录账号、密码、token 或访问口令
```

## 决策核验卡

新建、普通复查和复盘 Bug 写入 D/H 前，日志必须在“读取证据”后附以下七项；字段口径以 `agent/evidence-contract.md` 为准，所有确定性和待定结论都必须先使用 `agent/scripts/validate_bug_evidence_gate.py` 校验结构，确定性结论再通过证据充分性门槛。

```md
## 决策核验卡

- 备注因果链：完整评论中的现象、诊断、根因或已知限制。
- 客户问题识别：是否存在标题/描述前置的客户问题编号；若存在，写编号和客户测试用例的 complete / incomplete / missing 状态。
- 关联票：已读取的 Jira、关系和对本票结论的影响；无关联时写“已核验无直接关联票”。
- 证据画像与必查资料：逐项写画像选择/排除理由、必查动作状态、检索日期、入口、关键词、已读来源或不可用限制。
- 资料适用范围：来源、项目/车型、版本、触发方式、目标行为和 `exact / partial / mismatch / gap`。
- 冲突处理：预期、评论、关联票和正式资料的冲突及取舍。
- 唯一结论：状态、结论/依据/处理和责任方。
```

## 规则

- 日志要短，但必须能倒查“为什么这么写”。
- `涉及 Jira` 必须显式列出本次处理的每一个 Jira key；批量任务过多时可以引用同目录的 manifest，但 manifest 必须逐条列 key、负责人和表格行号。
- 批量日志必须为每个 Jira 单独写 `## PC-12345 决策核验卡` 形式的标题和完整七项卡；一张无 key 的公共卡不能覆盖多个 Jira。
- 只写“更新某段范围 / 批量处理若干条”而没有 Jira key，不计入该 Bug 的可追溯日志覆盖。
- 不记录账号、密码、token、测试账号明文或平台访问口令。
- 不可访问的资料也要写清楚限制，例如“仅 MasterGo 链接，当前不可读”。
- 决策核验卡缺字段、关联票未读、资料范围未标注或冲突未处理时，不记录为确定性结论，也不写入确定性 D/H。
- 旧线上记录缺少历史日志时不伪造补录；在后续触及该 Jira 时按完整流程核验并从当次开始留痕。
